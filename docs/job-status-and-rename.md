# Status job dan rename tanpa restart

Root cause UI: saved progress bersifat historical dan dapat masih berisi `CDC streaming` ketika registry sudah STOPPED, STOPPING atau FAILED. UI sekarang menampilkan lifecycle summary pada list/detail untuk terminal dan stopping states; raw saved progress tetap tersedia lewat API untuk investigation. QUEUED tidak memakai stale CDC phase. `STOPPING` tetap berarti lifecycle operation belum difinalisasi, bukan proof worker CDC sedang aktif.

Lease kosong saja tidak membuktikan asynchronous Delete pada control plane sudah selesai. Karena itu tidak ada automatic status rewrite atau auto-resubmit berdasarkan lease. Untuk orphan yang telah diperiksa, explicit Cancel memakai existing hard durable stop fence; checkpoint/receipts tetap dipertahankan. Production job 1-f sudah diselesaikan dengan cara ini setelah read-only check menunjukkan desired STOPPED, no lease, dan checkpoint stale.

Rename tersedia lewat tombol **Rename** dan `PATCH /api/jobs/{id}/name` dengan JSON `{"name":"Sync (btm)"}`. Input dibatasi 1–255 characters dan 4 KiB request. Hanya presentation metadata berubah: submission, desired state, lease, meta key dan pipeline tidak di-restart. Name column/config tersimpan atomik; worker progress/status writes tidak menimpa display name. Runtime connector log/snapshot labels tetap memakai nama saat constructor dibuat. Master views menyegarkan display name dari registry; original running connector config tetap immutable.

Regression UI, API, core, MySQL integration dan concurrent rename/view race PASS. Explicit stop integration mempertahankan PREPARED dan checkpoint; live/unrequested jobs tetap tidak diubah. Full unit suite dan recovery integration dijelaskan pada [fixture runbook](../tests/recovery/README.md). Rollback ke old worker dapat menimpa renamed job_name melalui legacy status writes; lakukan rename setelah semua worker memakai image baru. Recovery protocol rollback tetap mengikuti guards pada [checkpoint recovery](iceberg-checkpoint-recovery.md).
